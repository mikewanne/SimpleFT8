## Punkt 2 — `power_watts` und `tx_level` aus Settings raus

### Code-Audit-Ergebnis (von Claude verifiziert, nicht V4-Annahme!)

**`power_watts`** wird TATSÄCHLICH genutzt:
- `config/settings.py:52` Default 50
- `ui/mw_qso.py:580` **`tx_power=self.settings.power_watts`** im ADIF-
  Log-Eintrag (Logbuch-TX-Power-Feld)
- `ui/settings_dialog.py:627/801/852` Dialog-Load/Save/Reset
- `config/settings.py:224-225` Property-Getter

**Ersatz-Logik:** `power_watts` für ADIF aus dem **aktuell aktiven
Power-Preset** lesen (`control_panel.power_buttons`, default 10W).
ADIF wird damit ehrlicher — User sieht im Logbuch das was während des
QSO tatsächlich gesendet wurde, nicht den Settings-Default.

→ `ui/mw_qso.py:580`: `tx_power=self._current_power_watts` (vorhanden
in ControlPanel als P97-Tracker) oder via Helper-Property.

**`tx_level`** wird TATSÄCHLICH genutzt:
- `config/settings.py` Default 100
- `ui/main_window.py:1222` **`self.radio.tx_audio_level = self.settings.get("tx_level", 100) / 100.0`**
  beim Settings-Save (Live-Propagation).
- `ui/mw_radio.py:243` **`tx_level = min(75, self.settings.get("tx_level", 75))`**
  Cap auf 75% beim Radio-Connect (Kommentar: max 75%).
- `ui/settings_dialog.py:50/237/628/802` Dialog-Tooltip/Load/Save.

**Closed-Loop-Frage:** überschreibt der Closed-Loop in mw_tx.py den
tx_audio_level zwischenzeitlich? `mw_tx.py:795` liest `self.radio.tx_audio_level`,
Z.881 zeigt zur Statusbar. → Closed-Loop liest, justiert intern (z.B.
gegen Clipping), aber initial-Wert vom Setting wird zumindest beim
Connect angewandt.

**Ersatz-Logik:** Konstante 75% (entspricht heutigem Cap in mw_radio.py).
Settings entfernen, Radio bekommt initial 0.75. Closed-Loop justiert
nach Bedarf.

→ `ui/mw_radio.py:243`: `tx_level = 75  # P104: fest, war Settings`
→ `ui/main_window.py:1222`: Zeile raus (war Live-Propagation nach
Settings-Save, kein Setting mehr → kein Propagation nötig).

### Migration (config/settings.py:load)
```python
# P104 (v0.97.81): power_watts + tx_level entfernt — power aus aktuellem
# Power-Preset für ADIF, tx_level fest auf 75% (entspricht Cap).
self._data.pop("power_watts", None)
self._data.pop("tx_level", None)
```

## Architektur-Frage für V2/R1

1. **`_current_power_watts` als Source-of-Truth für ADIF:** ist
   `control_panel._current_power_watts` zur ADIF-Schreibzeit immer auf
   dem aktuellen Power-Preset? Verify nötig.
2. **Disabled-Style für rote Band-Buttons:** Mike will visuell rot
   sehen. Wenn `setEnabled(False)`, würde Qt das Grau-färben. Lösung:
   `setEnabled(True)` aber Click-Handler frühestmöglich return falls
   leer (mit Mini-Tooltip „keine Daten zum Löschen"). Oder doch
   Disabled mit explizitem `:disabled`-Stylesheet?
3. **Band-Reihenfolge:** absteigend Frequenz (10m..160m, wie Standard)
   oder aufsteigend Wellenlänge (10m..160m == steigend). Klassisch:
   aufsteigend Wellenlänge = absteigende Frequenz.
4. **60m-Band:** im RFPresetStore unterstützt? Andere Stellen im Code
   listen 60m nicht. Sicherheitshalber 60m nur wenn `enabled_bands`
   es enthält oder fest weglassen?
