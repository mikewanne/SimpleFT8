# P102 — V1: TUNE-Rechtsklick startet TUNE nicht + QMenu-Padding-Fehler

## Kontext

SimpleFT8 v0.97.77 (Mike Field-Test 21.05.2026, Radio AN).

## Bug 1 — Rechtsklick TUNE startet kein TUNE

**Mike-Spec (zentrale Frage):**

> Linker Mausklick auf TUNE geht. Rechter (mit Sekunden-Auswahl) geht nicht.
> Was kann da groß anders sein?

**Linksklick-Pfad (FUNKTIONIERT):**

`btn_tune.clicked` (Qt-Builtin-Signal von QPushButton) → connected an
`_RadioCard._on_tune_clicked` (control_panel.py:2052) → emittet
`tune_clicked` (Custom-Signal, `Signal(bool)`) → in ControlPanel reemittet:

`control_panel.py:1425`:
```python
self.btn_tune.clicked.connect(self._on_tune_clicked)
```

Aber: `self.btn_tune = radio_card.btn_tune` (control_panel.py:1424) und
`self._on_tune_clicked` ist auf `ControlPanel`! Also wird `btn.clicked`
direkt am `ControlPanel`-Slot connectet, KEIN `_RadioCard`-Zwischenschritt.

`ControlPanel._on_tune_clicked` (Z.1954):
```python
def _on_tune_clicked(self):
    self.tune_clicked.emit(self.btn_tune.isChecked())
```

→ `tune_clicked` ist ControlPanel-Signal. In main_window.py:761:
```python
self.control_panel.tune_clicked.connect(self._on_tune_clicked)
```

→ `MainWindow._on_tune_clicked` aus `mw_tx.py:78`. Funktioniert!

**Rechtsklick-Pfad (FUNKTIONIERT NICHT):**

`btn_tune.customContextMenuRequested` → connected an
`_RadioCard._on_tune_button_context_menu(pos)` (control_panel.py:1000).
Diese Methode öffnet Menü mit Action-Items „TUNE 10s/15s/20s".

User klickt Item → `_emit_override(s)` (Closure innerhalb der Methode):
```python
def _emit_override(s: int):
    debug_log("P101", f"menu-action TUNE {s}s clicked → emit signal")
    self.tune_override_requested.emit(s)
```

→ `self` ist `_RadioCard`. `self.tune_override_requested` ist `_RadioCard`-
Signal (Z.772, `tune_override_requested = Signal(int)`).

Connection an MainWindow:

**HEUTE (v0.97.77, Variante A nach DeepSeek-Empfehlung):**
`main_window.py:763` ruft `self.control_panel.on_tune_override_requested(self._on_tune_override)`,
das macht `self._radio_card.tune_override_requested.connect(callback)`
(control_panel.py:2060).

**Debug-Log-Beweis aus Mike-Field-Test 21.05. um 05:26:52:**
```
[P101] menu-action TUNE 10s clicked → emit signal
                    ↑
   _emit_override läuft, ruft self.tune_override_requested.emit(10)
   → KEINE WEITERE Log-Zeile, kein _on_tune_override called
```

→ Signal `_RadioCard.tune_override_requested` wird emittet, aber der
direkt-connectete `_on_tune_override`-Slot in MainWindow läuft nicht.

**Kritische Beobachtung:**

Linksklick `btn_tune.clicked → _on_tune_clicked → tune_clicked → MainWindow._on_tune_clicked`
ist auch ein 2-Stage-Signal-Hop. Der Rechtsklick-Pfad ist 1-Stage (direkt
ans _radio_card) — sollte EINFACHER sein.

**Mike's Frage präzise:** Was unterscheidet `tune_clicked.emit(bool)` von
`tune_override_requested.emit(int)`? Beide sind Custom-Signals derselben
Klasse-Hierarchie. Beide laufen im selben GUI-Thread. Linksklick emittet
und der Slot läuft. Rechtsklick emittet und der Slot läuft NICHT.

## Bug 2 — QMenu-Padding falsch positioniert

**Mike-ASCII-Spec:**

```
AKTUELL:  Il   text         (Häkchen klebt am linken Rand, danach viel Lücke, dann Text)
SOLL:     I L text          (Border, 1 Leerzeichen, Häkchen, 1 Leerzeichen, Text)
```

Wobei `I` = vertikaler Rand des Mitteilungsfensters, `L` = Häkchen-Symbol ✓.

**Heutiger Stylesheet (qso_panel.py + rx_panel.py):**

```css
QMenu::item { padding: 4px 20px 4px 32px; }
QMenu::indicator { width: 14px; height: 14px; margin-left: 8px;
    subcontrol-position: left center; }
```

→ Mike sieht: Indicator klebt am LINKEN Border, dann ~18px Lücke bis Text.
`margin-left: 8px` greift offensichtlich nicht in PySide6/macOS.

## Hypothesen Bug 1

**H1**: `_RadioCard.tune_override_requested`-Signal wird beim
`_emit_override`-Call auf einer **anderen Instanz** aufgerufen als die in
`self._radio_card` referenzierte. Closure-`self` zeigt evtl. auf ein
abandoned-Widget.

**H2**: Signal-Connection wird durch Qt zwischen `connect()` und `emit()`
**disconnectet**, evtl. durch Widget-Lifecycle (Parent-Reparenting).

**H3**: `_emit_override` (innere Closure in
`_on_tune_button_context_menu`) hält Closure-`self` aber Qt geht den Slot
verloren weil der QAction-Lifetime an das Menü gebunden ist und Menü
nach `exec()` zerstört wird (Action-deleteLater) → Signal-Connection
geht mit verloren? Unwahrscheinlich da emit ja noch geht.

**H4**: `Signal(int)`-Type-Mismatch. `tune_clicked = Signal(bool)`,
`tune_override_requested = Signal(int)`. Vielleicht Qt-PySide6-Bug bei
`int`-Signal mit dynamischem Sender.

**H5**: ControlPanel-Helper `on_tune_override_requested` wird nach
`__init__` von `_radio_card` aufgerufen, aber `_radio_card`-Instanz
ist zu dem Zeitpunkt schon GC'd? Sehr unwahrscheinlich, da
`self._radio_card = radio_card` (Instanz-Attribut).

**H6**: Doppel-Connect — Es gibt einen zweiten, früheren Connect der
`_emit_override` direkt an etwas anderem hängt (z.B. `closeAllWindows`),
und der Override-Slot wird übergangen. Code-Audit nötig.

**H7 (Mike-Spec-Lead)**: Was machen die zwei Pfade strukturell anders?
- Linksklick: `btn.clicked` ist Qt-Builtin → ControlPanel-Slot. Sender
  ist `QPushButton` (`btn_tune`). Slot in `ControlPanel` (Outer-Klasse).
- Rechtsklick: `btn.customContextMenuRequested` ist Qt-Builtin →
  `_RadioCard`-Slot (Inner-Klasse). Slot öffnet QMenu, Action.triggered
  → `_emit_override` → `self.tune_override_requested.emit(s)`. Sender
  ist `_RadioCard`-Instanz.

  → **Unterschied**: Linksklick Sender = `btn_tune` (Qt-Widget), Rechtsklick
  Sender = `_RadioCard` (Custom-Widget). Wenn `_RadioCard`-Signale generell
  nicht an MainWindow zustellbar sind (Parent-Hierarchie?), wäre das die
  Ursache. Aber `collapse_changed = Signal(bool)` (Z.770) ist auch ein
  `_RadioCard`-Signal und das funktioniert (Mike kollabiert die Kachel).
  → Verworfen.

## Hypothesen Bug 2

**P1**: `margin-left` für `QMenu::indicator` wird auf macOS von PySide6
ignoriert. Stattdessen muss man `padding-left` am Indicator setzen.

**P2**: Indicator hat eigene Default-Geometrie die `margin-left`
überschreibt. Erforderlich: `subcontrol-origin: padding` zusätzlich.

**P3**: Mike sieht eigentlich GAR KEIN Häkchen-Symbol sondern einen
QMenu-Default-Indicator-Marker den man nicht via Stylesheet beeinflussen
kann — und der ist links-bündig am Border.

**P4**: Pragmatischer Workaround: Indicator komplett verstecken
(`QMenu::indicator { width: 0; height: 0; }`), Häkchen-Symbol manuell
in den Action-Text packen (`✓ Even/Odd-Tag` / `   Even/Odd-Tag`).
Dann ist Positionierung pixelgenau kontrollierbar via `padding-left` +
String-Whitespace.

## V1-Strategie

### Bug 1
**Phase 1** — Live-Diagnose: Code-Audit gegen H1+H6 + Closure-Analyse.
**Phase 2** — Wenn keine Code-Ursache: Variante X (Callback komplett
ohne Signal, statt Signal direkt Funktion-Property an `_RadioCard`).

### Bug 2
**Variante P4 (KISS)**: Indicator verstecken, Häkchen via Action-Text-
Prefix. Pixelgenau, plattformunabhängig.
