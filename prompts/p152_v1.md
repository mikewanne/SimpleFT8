# P152 V1 — Weak-Decode-Logging (SNR ≤ -21 dB in eigene Liste)

## Trigger / Use-Case

P150 hat `kMin_score=10→4` gesenkt. Wir haben KEINE Vorher-Werte zum
Vergleich. Mike-Idee: ab jetzt jeden schwachen Decode (SNR ≤ -21 dB) in
eine eigene Liste schreiben → empirischer Beweis ob der Fix tiefe Decodes
bringt. Mike-Field gerade live: 15m mau, sieht 2 Stationen bei -22 dB.

**Mike-Wahl (AskUserQuestion 28.05.):**
- Eigene Datei, IMMER an (kein Setting, kein Toggle)
- Schwelle SNR ≤ **-21 dB** (umfasst die ganze „neue" Zone, -21 war alte
  Decoder-Grenze)

## Design

### Neues Modul `core/weak_decode_log.py`

Analog `core/debug_log.py`, ABER:
- **Always-on** (kein `_enabled`-Toggle — Mike will keine Settings)
- Eigene Datei `~/.simpleft8/weak_decodes_YYYY-MM-DD.log` (UTC-Datum)

### Hook in `ui/mw_cycle.py:_on_cycle_decoded`

Nach `_assign_slot_parity(messages)` (Z. 87), VOR den mode-Branches.
Für jede message mit `snr <= WEAK_SNR_THRESHOLD`:

```python
from core.weak_decode_log import log_weak_decode, WEAK_SNR_THRESHOLD
for _m in messages:
    if getattr(_m, 'snr', 0) <= WEAK_SNR_THRESHOLD:
        log_weak_decode(_m.snr, _m.raw, _m.freq_hz,
                        self.settings.band, self.settings.mode)
```

**Warum dieser Hook:**
- `_on_cycle_decoded` läuft im GUI-Thread (Slot-Signal), hat `self.settings`
  (band/mode) + volle messages-Liste
- Nach `rx_active`-Check (Z. 84-85) → kein Logging wenn RX aus
- VOR mode-Branches → unabhängig von diversity/normal/dx_tune
- `messages` kann leer/None sein → for-loop über `messages or []`

### Cleanup-Aufruf in `main.py`

Neben dem bestehenden `debug_log.cleanup_old_files` (Z. 418-419):

```python
from core import weak_decode_log as _wdl
_wdl.cleanup_old_files(keep_days=7)
```

## FT8Message-Felder (verifiziert)

- `.snr` (int) — Signal-SNR
- `.raw` (str) — komplette Nachricht z.B. "DL1ABC OE5XYZ -15"
- `.freq_hz` (int) — Audio-Frequenz
- `.caller` = field2 (property)

`band`/`mode` aus `self.settings.band` / `self.settings.mode`.

## Was NICHT gebaut wird

- Kein Settings-Toggle (Mike: immer an)
- Keine UI-Anzeige (reine Datei für Mike + Claude zum Lesen)
- Keine Aggregation/Statistik (nur rohe Zeilen, Mike wertet manuell aus)
- Kein Bezug zu P150-dylib (unabhängig — loggt was der Decoder liefert,
  egal welche kMin_score-Schwelle aktiv ist)

## Risiko

- **Disk-Wachstum:** bei vielen schwachen Decodes große Datei. Mitigation:
  keep_days=7 + 1 Zeile/Decode ist winzig (~60 Bytes). 100 schwache
  Decodes/Tag = 6 KB/Tag. Irrelevant.
- **Performance:** File-Append pro schwachem Decode im GUI-Thread. Bei
  schlechten Bedingungen (Mike's Use-Case) sind das wenige pro Slot →
  vernachlässigbar. Bei sehr vielen: Lock + append ist schnell.
- **Threading:** GUI-Thread-Hook, Lock im Modul → safe.
